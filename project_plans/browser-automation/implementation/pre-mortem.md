# Pre-mortem: browser-automation
**Date**: 2026-08-06

## Failure Modes

| # | Failure | First Symptom | Prevention | Severity |
|---|---------|--------------|------------|----------|
| 1 | The wasm adapter ships with zero executable tests — Tasks 4.1.1/4.1.2/4.2.1/4.2.2/2.5.3 all write ACs phrased "in a Node test harness" but no Epic 6 story creates one, so `stapler_browser_*` on the wasm daemon is verified only by manual spot-check, if at all. | A caller running the wasm daemon hits `stapler_browser_click` and gets a raw, unmapped JS exception (or a hang) that native's test suite never would have caught, because nothing ever executed `browser.js`'s glue functions against a real or mocked `page`. | Add an explicit Epic 6 story: stand up a minimal Node test runner (even a plain `node --test` script invoking the glue functions with a mocked `playwright-core` `page`) and make it a required, non-optional CI/local-check step before Story 6.2 is considered done — not just documented as a future gap. | P1 |
| 2 | The hand-rolled native AX-tree walk (`ax.rs`) produces role/name labels that are technically non-empty but not distinguishable/reliable enough to build a click/type locator on a real page (e.g. generic roles, missing/duplicate names, wrong node pruning) — Success Metric #5's actual bar ("sufficient to build a click/type locator from it") is never gate-checked because no task cites that metric directly. | `stapler_browser_snapshot` returns a tree, so the daemon and integration test "pass," but an agent using it can't reliably tell the button from the input, or picks the wrong `ref`, and click/type silently act on the wrong element. | Add an explicit acceptance task under Story 3.1/6.2 that asserts, against the real mock page, that the button and input nodes have *distinct, human-legible* `role`+`name` pairs (not just ">=1 non-ignored child") — i.e. directly test Success Metric #5's wording, not a weaker proxy. | P1 |
| 3 | A `click`/`type_text` call whose action itself triggers a top-level navigation (form submit, `location.assign`) hits chromiumoxide's "execution context destroyed" mid-call, because Story 3.3 has no designed handling for this beyond the separate `FrameNavigatedGuard` (which reacts *after* navigation, not during the in-flight call) — flagged unchanged across two adversarial-review rounds. | A user clicks a "Submit" button in a real form-driven flow — the single most common browser-automation use case — and gets a raw CDP/chromiumoxide error instead of the post-submit snapshot the tool is supposed to return. | Add a task to Story 3.3 that explicitly catches "execution context destroyed"/target-navigated errors during click/type dispatch, waits for the resulting navigation to settle (reusing the same wait-for-load + priming-retry logic Task 3.2.1 already has for `navigate`), and returns a fresh snapshot with a `note` — rather than leaving the dispatch's error path undefined. | P2 |
| 4 | Success Metric #3 (idle reaping) is only verified via the reaper's internal map-scan in a unit test (Task 6.1.3); no test drives the public session lifecycle (navigate → wait past timeout → call again) and asserts `PortError::NotFound`, so a bug in the *lookup* path (not the reaper) that leaves a reaped session appearing to still work would ship undetected. | An idle session gets reaped internally, but a subsequent `stapler_browser_click` against its `session_id` doesn't cleanly return "not found" — instead it hangs, panics, or (worse) silently operates on a stale/closed `Page` handle, because the reaper-eviction and call-lookup code paths were only tested in isolation, never together. | Extend Task 6.1.3 (or add a new task) to mirror Task 2.5.2's crash-path pattern: after simulated reaping, call `browser_navigate`/`click`/`snapshot` against the evicted `session_id` and assert it surfaces `PortError::NotFound` end-to-end — the same treatment already applied to the crash path but not carried over to the reaper path. | P2 |
| 5 | The reaper task panics mid-lifetime (most plausibly a `RefCell` borrow held across an `.await` — the plan's own Step 0.5(a) names this as the chosen design's core weakness, "enforced by task-level review, not the type system") and nothing detects it until daemon shutdown, if ever, since Story 2.4's `JoinHandle` check only runs at shutdown and this isn't recorded as an accepted risk anywhere in the plan. | Chrome tabs/processes accumulate silently over days/weeks of daemon uptime with no error surfaced to the caller or logged anywhere — a slow resource leak that looks like "the daemon got slower" rather than an obvious crash, discovered only when the box runs out of memory or someone notices `ps` full of zombie `chrome` processes. | Add a lightweight liveness check: after each reaper scan iteration, write a heartbeat timestamp the shutdown-time (or a periodic) check can compare against wall-clock time, and log a warning if the reaper hasn't ticked within `2 * scan_interval`; alternatively, wrap the reaper's scan body in a `catch_unwind`/`Result`-returning loop that logs-and-restarts rather than silently dying. Record this explicitly in Unresolved Questions if not fixed pre-ship. | P3 |

## P1 Items (address before implementation)
- [x] #1 (wasm test harness) — **Addressed by scope narrowing, not by adding a harness**: `requirements.md`'s Success Metrics bullet now explicitly scopes the full navigate→click→type→snapshot round-trip requirement to the native adapter only, citing the wasm/native behavioral-parity-testing rabbit hole; wasm retains only its single-call smoke test. The underlying gap (no Node test harness exists) is unchanged, but it is no longer silently assumed away by ACs — see adversarial-review.md Round 2's "wasm-side test-harness gap still unresolved" concern, which remains open and tracked there.
- [x] #2 (AX role/name fidelity ungated) — **Addressed**: Task 3.2.1 (plan.md) gained an AC requiring the mock test page to render ≥2 distinguishable interactive elements (a button and a text input) with different role/name pairs, and asserting the snapshot can tell them apart by name/role — not just count non-ignored child nodes.
