# Implementation Plan: browser-automation

Source: `project_plans/browser-automation/requirements.md`, `research/*.md`, GitHub issue #7.

## Step 0.5 — Creative Pass: session-map + reaper design alternatives

Three approaches were considered for holding session state (`SessionId -> Page`) and
expiring idle sessions, before committing to one.

**(a) `Rc<RefCell<HashMap<SessionId, SessionEntry>>>` + `tokio::task::spawn_local` reaper — CHOSEN**
Mirrors the existing `SourceLocks` pattern (`crates/core/src/tools/docs.rs:303`,
`RefCell<HashSet<SourceId>>` + RAII guard). The daemon is single-threaded
(`current_thread` runtime + `LocalSet`, `crates/cli/src/main.rs:20-31`) specifically so
`!Send` types work, which is why `NativeBrowser` and every port adapter already use `Rc`,
never `Arc`. A reaper as a `spawn_local` task holding an `Rc` clone of the session map is
the natural extension of that idiom.
- Strength: zero new concurrency primitives; one `RefCell` borrow discipline to reason
  about (same "never hold a borrow across `.await`" rule already enforced for
  `SourceLocks`); the reaper task is just another `spawn_local` alongside the existing
  CDP event-drain `tokio::spawn` in `NativeBrowser::launch()`.
- Weakness: `RefCell` gives no compile-time protection against a borrow held across an
  `.await` point — a mistake here panics at runtime (`already borrowed: BorrowMutError`)
  rather than failing to compile, so the discipline is enforced by task-level review, not
  the type system.

**(b) Actor task owning all session state, tool calls talk to it over an `mpsc`/oneshot channel — REJECTED**
Each `BrowserDriver` method would send a request to a dedicated task and await a
one-shot response instead of touching a shared map directly.
- Strength: session mutation is trivially serialized (only the actor touches the map), so
  there is no `RefCell` borrow-across-`.await` hazard at all.
- Weakness: foreign to this codebase's idiom — nothing else in `crates/core`/`crates/native`
  uses actor+channel; it would require every `BrowserDriver` trait method to round-trip
  through a channel even for read-only operations, a materially larger diff with no
  existing precedent to model it on, for a benefit ((a)'s only real weakness) that
  disciplined `RefCell` usage already gets for free given the single-threaded runtime.

**(c) `Arc<Mutex<HashMap<SessionId, SessionEntry>>>` — REJECTED**
The conventional multi-threaded-Rust answer to shared mutable state.
- Strength: well-understood, works if the runtime ever became multi-threaded.
- Weakness: this is exactly the primitive the codebase deliberately avoids —
  `research/architecture.md` and every existing port adapter chose `Rc`/`RefCell` +
  `current_thread`/`LocalSet` specifically so the same core logic stays `!Send`-compatible
  for the wasm adapter (wasm-bindgen types are `!Send`). Introducing `Arc<Mutex<_>>` here
  would be the first `Send`-oriented primitive in the codebase and a real idiom break that
  a reviewer should flag.

Decision: **(a)**, matching `research/architecture.md`'s recommendation and the
`SourceLocks` precedent already in the codebase.

## Step 1 — System Type

This is a **stateful port extension plus a background reaper task inside an existing
hexagonal-architecture daemon** — not a new service, new crate, or new process. It adds:
one new/extended port trait (`BrowserDriver`), new port-level and schema-level types, one
new tool module (`crates/core/src/tools/browser.rs`), adapter-side session-lifecycle state
in `crates/native/src/browser.rs` (native) and `crates/wasm/src/glue/browser.js` (wasm),
and daemon tool registration in both `crates/cli/src/main.rs` and `crates/wasm/src/lib.rs`.

## Step 2 — Domain Glossary

| Term | Definition |
|---|---|
| `SessionId` | Opaque string identifying one live browser session (one open `Page`/tab); generated by the adapter, never by core, never by the caller. |
| `BrowserSession` | The adapter-owned state for one session: a `chromiumoxide::Page` (native) or a JS `Page` handle (wasm), the session's `last_used` timestamp, and its `latest_snapshot` ref table. |
| `SessionRegistry` | The `Rc<RefCell<HashMap<SessionId, BrowserSession>>>` held by `NativeBrowser`, mapping live sessions to their state. |
| `SessionIdleReaper` | The `spawn_local` background task that periodically scans `SessionRegistry`, closes and evicts any session whose `last_used` is older than `SESSION_IDLE_TIMEOUT`, and is `.abort()`-ed at daemon shutdown before `NativeBrowser::close()` runs. |
| `SESSION_IDLE_TIMEOUT` | Named constant, `Duration::from_secs(300)` (5 minutes) — how long a session may sit with no `navigate`/`click`/`type_text`/`snapshot` call before the reaper closes it. |
| `AxNode` | One node of an accessibility-tree snapshot: `ref` (opaque locator id, valid only within its parent `AxSnapshot`), `role` (ARIA role, resolved from CDP's pre-computed value or implicit HTML mapping), `name` (accessible name, pre-computed by Chromium/Playwright), `children: Vec<AxNode>`. |
| `AxSnapshot` | A full accessibility-tree capture for one session at one point in time: `root: AxNode`, `url` (page URL at capture time), `truncated: bool` (set when the tree was capped for size, mirroring `SearchDocsOutput`'s truncation flag). |
| `Locator` | A newtype (`pub struct Locator(pub String)`) wrapping an opaque `ref` id from the most recent `AxSnapshot` for that session. **Not** a role+name pair — see Pattern Decisions. Scoped to one `AxSnapshot`; stale after the next navigation or mutation. |
| `NavigateResult` | Port-level return type of `BrowserDriver::navigate`: `session_id: SessionId`, `final_url: String`, `snapshot: AxSnapshot`. |
| `blocked_host_reason` | Existing SSRF guard (`crates/core/src/tools/webcrawl.rs:154`) — given a `Url` and `NetworkPolicy`, returns `Some(reason)` if the host resolves to a private/loopback/link-local address and should be blocked. Reused (with visibility widened) for browser-automation navigation checks. |
| `NetworkPolicy` | Existing enum (`webcrawl.rs`) — `Enforce` vs `AllowPrivateNetworks`; controls whether `blocked_host_reason` blocks private-network targets. Read via `STAPLER_MCP_ALLOW_PRIVATE_NETWORKS` env var in tests. |
| `FrameNavigatedGuard` | New behavior (native + wasm): on every in-session navigation event — including ones triggered by `click`/`type_text` submitting a form or running `location.assign()` — re-run `blocked_host_reason` against the new URL. If the triggering call's own dispatch caused the navigation, that **same call** fails (Task 3.3.1/3.3.2's grace-period check); otherwise the *next* call to that session fails. Either way, a blocked host's content is never handed back as a normal-looking snapshot. Closes the SSRF gap identified in `research/pitfalls.md`. |
| `PortError::NotFound` | New `PortError` variant (`NotFound(String)`) for "no such session" / "no such locator" conditions, distinct from `Other`/`Io`/`Timeout`. |

13 terms.

## Step 3 — Technology Validation & Pattern Selection

**Stability/licensing/security**: no new Cargo or npm dependencies (confirmed in
`research/stack.md` and `research/build-vs-buy.md`); `chromiumoxide` 0.9.1 and
`playwright-core` are already-adopted, already-vetted deps. The one security-relevant gap
is the SSRF guard scope, addressed explicitly below (not silently dropped).

**`SessionId` generation**: no `uuid` crate present in `Cargo.lock` (checked). Rather than
add a dependency for this, `NativeBrowser` generates ids from a `Cell<u64>` counter plus
the adapter's clock: `format!("sess-{:x}-{:x}", clock.now_millis(), counter)`. Collision-free
within one daemon process lifetime, zero new dependencies.

**Locator format — resolved to ref-based (not role+name)**: `research/features.md`,
`research/ux.md`, and `research/pitfalls.md` all converge on playwright-mcp's model: an
opaque `ref` id scoped to the latest snapshot, invalidated on navigation. Exposing
role+name directly as an alternative `click`/`type` input (as `requirements.md`'s original
framing suggested) would require two resolution code paths (by-ref vs by-role+name) and
two staleness stories; the ref-based model needs only one, and the "refs die at next
snapshot" staleness boundary is itself a documented UX feature (`research/ux.md` line 39-41:
forces re-observation, the single most common class of browser-automation bug). Role+name
matching still happens internally (that's how `snapshot` assigns `ref`s to nodes in the
first place) — it just isn't exposed as a second locator input shape in v1.

**Idle timeout — resolved to 5 minutes**: `SESSION_IDLE_TIMEOUT: Duration =
Duration::from_secs(300)`, a named constant in `crates/native/src/browser.rs`. Long enough
to survive a multi-step agent think-pause between tool calls, short enough to bound zombie
Chrome tab accumulation from abandoned sessions.

**`navigate` session-reuse semantics — resolved**: no `session_id` in `BrowserNavigateInput`
→ always create a brand-new session (new `SessionId`, new `Page`/tab), matching
`fetch_page`'s existing "fresh tab per call" precedent (`crates/native/src/browser.rs:9-11`)
for the no-session case. `session_id` given and still present in the `SessionRegistry` →
re-navigate within that existing session (reuse the same `Page`, same `SessionId`), bump
`last_used`, and treat all `ref`s from that session's prior snapshot as stale (a fresh
`AxSnapshot` is returned). `session_id` given but not found (evicted by the reaper or never
existed) → `PortError::NotFound`, surfaced as the session-not-found error described below —
never silently falls back to creating a new session, since that would silently discard the
caller's intent to continue an existing flow.

**`PortError` extension — resolved to add `PortError::NotFound(String)`**: grepped
`PortError::` usage across the workspace; only `crates/core/src/ports.rs`'s own `Display`
impl and a partial match in `crates/wasm/src/socket.rs:32` reference variants outside
construction sites, so adding a variant is low blast-radius (confirmed, not assumed). A
dedicated variant lets `tools/browser.rs` reliably detect "not found" conditions and
produce the specific, actionable message `research/ux.md` §3 mandates, instead of
string-sniffing a generic `Other(String)`.

**`blocked_host_reason` visibility — resolved to `pub`**: currently a private `fn` in
`webcrawl.rs:154`. The tool-layer navigate-time check (`tools/browser.rs`, same crate) only
needs `pub(crate)`, but the native adapter's `FrameNavigatedGuard` (different crate,
`crates/native`) needs to call it too, so it is widened to `pub fn blocked_host_reason` and
re-exported from `crates/core/src/tools/webcrawl.rs` (already `pub mod webcrawl`, so no
further re-export plumbing needed).

**AX-tree walking pattern**: hand-rolled traversal over `chromiumoxide_cdp`'s typed
`Accessibility.getFullAXTree`/`queryAXTree` structs, isolated in a new module
`crates/native/src/ax.rs` (kept separate from `browser.rs`'s session-lifecycle concerns).
Confirmed via `research/build-vs-buy.md`: CDP already returns Chromium's pre-computed
`role`/`name` per node — the new code is traversal + `ref` assignment + hidden-node pruning,
not an accname port.

**wasm adapter pattern**: thin JS glue directly against `playwright-core`'s
`page.ariaSnapshot()` / `page.getByRole()` (current API; `page.accessibility.snapshot()` is
legacy per `research/stack.md`), following the existing `jsNavigateAndExtract` pattern in
`crates/wasm/src/glue/browser.js`.

**wasm reaper — resolved to attempt a JS `setInterval` reaper**: the wasm session map
lives entirely in JS (the Rust `WasmBrowser` struct stays a zero-field unit type, forwarding
`session_id` strings across the `wasm_bindgen` boundary same as today). A `setInterval`
in `browser.js` scans the JS-side session `Map` and closes idle pages, mirroring the native
reaper's behavior. This keeps native/wasm parity instead of relying on the `Embedder`
doc-comment precedent (`ports.rs:139-148`) to justify a silent asymmetry — parity is
achievable here at low cost (a `setInterval` is simple JS), unlike `Embedder`'s case.

**SSRF `frameNavigated` hook — resolved to implement, not defer**: `research/pitfalls.md`
calls this "the most important pitfall to design against." Implemented as an explicit
story (Epic 3, Story 3.4) on both native (chromiumoxide `Page::event_listener::<EventFrameNavigated>()`)
and wasm (`page.on('framenavigated')`), re-running `blocked_host_reason` against every
in-session navigation, not just the initial `navigate` call.

## Observability Plan

- Reaper eviction is logged (`eprintln!` matching this repo's existing logging convention —
  no structured logging framework is present in `crates/native`/`crates/cli` today) with
  the evicted `SessionId` and idle duration, so zombie-session cleanup is visible in daemon
  stderr without adding a new dependency.
- `PortError::NotFound` and `FrameNavigatedGuard` blocks are surfaced as tool-call errors
  (visible to the calling agent and, transitively, to whatever wraps the daemon's stdout/
  stderr) — no separate metrics/tracing pipeline exists in this codebase to hook into, so
  none is added.
- The reaper's `JoinHandle` result is checked (not just held) at shutdown, matching
  `research/pitfalls.md`'s warning that a panicking reaper task fails silently unless the
  handle's result is inspected.

## Risk Control

| Risk | Mitigation | Where |
|---|---|---|
| Zombie Chrome tabs from abandoned sessions | `SessionIdleReaper` + `SESSION_IDLE_TIMEOUT` | Epic 2 |
| Reaper evicts a session mid-call (TOCTOU) | Reaper's eviction removes the entry from `sessions` synchronously (single `borrow_mut()`, no `.await` inside it) *before* `.await`ing `page.close()` on the now-exclusively-owned, already-detached entry — so a concurrent lookup during the close can never observe a live-looking map entry. Combined with Task 2.3.1 bumping `last_used` synchronously at call entry, before any `.await`, so an in-flight call is never seen as idle by a concurrent reaper scan. | Epic 2, Story 2.3 |
| Tab/target crash mid-session (`Target.targetCrashed`) | Crash listener sets a `crashed` flag on the session; next call detects it, evicts the entry, and returns the distinct `PortError::SessionCrashed` (not `NotFound` — different failure semantics the caller needs to distinguish: "dead but still mapped" vs. "gone") | Epic 2, Story 2.5 |
| SSRF via in-page navigation (click/type triggering `location.assign()` or form submit) | `FrameNavigatedGuard` re-checks `blocked_host_reason` after every top-level navigation event within a session. If the call that triggered the navigation is still in flight (its own click/type dispatch), Task 3.3.1/3.3.2's grace-period check fails **that same call**; otherwise the *next* call is blocked. Either path ensures the blocked page's content is never handed to the caller. This does **not** prevent the initial request from going out (CDP's `frameNavigated` fires after the navigation commits, not before), and does **not** cover subresource requests (`fetch`/`XHR`/`<img>`/etc. triggered by page JS with no top-level navigation at all) — see Unresolved Question 4, an accepted, explicitly out-of-scope gap for this pass | Epic 3, Story 3.4 |
| Zombie Chrome process on adapter error paths (no crash-path fallback in `NativeBrowser::close()`) | Out of scope for this feature — pre-existing gap noted in `research/pitfalls.md`, not introduced or worsened by session support; recorded in Unresolved Questions below rather than silently ignored | — |
| Reaper panic goes unnoticed | Check `JoinHandle` result at shutdown | Epic 2, Story 2.4 |
| Stale `ref` used after navigation/mutation | Every `navigate`/`click`/`type_text` call invalidates the session's prior `AxSnapshot` and returns a fresh one; `snapshot`/click/type on an unknown `ref` returns `PortError::NotFound` with the UX-mandated actionable message | Epic 4 |

## Unresolved Questions

1. `NativeBrowser::close()` has no crash-path fallback (a Chrome process can leak if the
   daemon is killed with `SIGKILL` rather than exiting cleanly). Pre-existing to this
   feature; not addressed here. Recorded per `research/pitfalls.md` rather than silently
   dropped — a future issue should track adding a process-group kill or PID-file cleanup on
   next daemon startup.
2. Ambiguous-match UX (`research/ux.md` §4: "N elements match role={role} name={name}") does
   not apply under the ref-based locator decision, since `snapshot` assigns each node a
   distinct `ref` regardless of duplicate names — recorded here so it isn't mistaken for a
   dropped requirement; it's resolved by the locator-format decision itself.
3. Diff-oriented/truncated auto-snapshots after mutation (`research/ux.md` §2's "only emit
   if the tree actually changed" refinement) is scoped out of v1's Epic 4 — v1 always
   returns a full (but depth/node-capped, `truncated: true` when capped) snapshot after
   `click`/`type_text`. Diffing is a token-economy optimization, not a correctness
   requirement; left for a follow-up once real usage data shows it's needed.
4. **`FrameNavigatedGuard` does not intercept subresource-level SSRF.** `research/pitfalls.md`
   §4 names this as the single most important pitfall: a page reached via a URL that passed
   the `navigate`-time `blocked_host_reason` check can still embed a hidden `<img>`, `fetch()`,
   or `XHR` pointed at `http://169.254.169.254/` or an internal admin endpoint, triggered by
   page JS with **no top-level navigation event at all** — `FrameNavigatedGuard` only listens
   to `Page.frameNavigated`, never touches CDP's `Network`/`Fetch` domains, so this class of
   request is invisible to it and completes with no guard in the loop, before or after the
   fact. Real interception would require chromiumoxide's `Fetch` domain (request pausing/
   inspection) on both native and wasm (`page.route()` on the Playwright side) — a materially
   larger scope increase (intercepting and re-authorizing every subresource request the page
   makes, not just top-level navigations) than this pass's appetite covers. Explicitly
   **out of scope for this pass**, not silently assumed covered by the Risk Control table's
   `FrameNavigatedGuard` row above; recorded as a known, accepted gap and a fast-follow
   candidate (`Fetch`-domain request interception for browser-automation sessions) rather than
   attempted here.
5. **SPA (`pushState`/`replaceState`) navigation is not distinguished from a real top-level
   navigation.** `FrameNavigatedGuard` (Task 3.4.2) reacts to CDP `Page.frameNavigated`, which
   fires for same-document SPA navigations too, but Unresolved Question 3's diffing note and
   Task 3.2.1's post-navigate priming-retry logic were both designed with full page loads in
   mind — an SPA route change may not fire a `load` event at all, so `navigate`'s
   wait-for-load step could time out or behave oddly if a caller ever pointed `navigate` at an
   SPA-only route transition rather than a fresh URL load. Not fixed in this pass (v1's
   real-world test pages, Story 6.2, are plain multi-page-load HTML, not SPAs); recorded as a
   known gap for whoever first hits it against a real SPA target.
6. **`SESSION_IDLE_TIMEOUT` (Task 2.1.2) is a compile-time `const`, not a runtime-configurable
   value.** This satisfies requirements.md's "easy to find/change" bar literally (one named
   constant, not a magic number scattered across call sites) but not an operator-tunable
   config surface (env var, config file, CLI flag) — no other tool in this codebase has one
   either, so this matches existing project convention rather than falling short of it.
   Recorded so it isn't mistaken for an oversight; revisit if a future need for
   per-environment tuning (e.g. a shorter timeout in CI) ever arises.
7. **`truncated: true` has no corresponding "get more" affordance.** `AxSnapshot.truncated`
   (Task 1.1.1) tells a caller the tree was capped for size, but v1 ships no subtree-fetch or
   pagination tool to retrieve the rest — a caller who hits `truncated: true` on a very large
   page has no recourse beyond `click`ing further into the page to narrow what a *subsequent*
   snapshot captures. Explicitly out of scope for this pass (pagination/subtree APIs are a
   materially larger surface, matching the same appetite reasoning as Unresolved Question 4);
   recorded as a fast-follow candidate rather than silently assumed covered by the `truncated`
   flag's mere presence.
8. **`aria-ref=` locator's strict-mode / multi-match behavior is unspecified.** Task 4.2.1's
   `page.locator(\`aria-ref=${ref}\`)` fix for the wasm TOCTOU gap assumes each `ref` resolves
   to exactly one element, but Playwright locators throw on ambiguous multi-match under strict
   mode by default — not currently a concern for `aria-ref=` specifically (each ref is
   generated as unique per snapshot), but not explicitly tested either. Recorded so a future
   `playwright-core` version change in `aria-ref=`'s matching semantics isn't a silent
   behavior change; add a regression test if this class of bug is ever observed.
9. **No documented default for `timeoutSeconds` when a caller omits it.** `BrowserClickInput`/
   `BrowserTypeInput`/etc.'s `timeout_seconds: Option<u32>` (Task 1.2.x) has no stated fallback
   value in this plan when `None` — each adapter presumably has its own default (chromiumoxide's
   / playwright-core's built-in timeout), but that default isn't pinned to a specific number
   anywhere a caller or future maintainer can look it up. Not blocking (both underlying
   libraries have sane built-in defaults), but worth pinning explicitly (e.g. a
   `DEFAULT_ACTION_TIMEOUT_MS` constant mirrored across both adapters) as a fast-follow if
   inconsistent native/wasm default timeouts ever cause confusing behavioral drift.
10. **Native's `verify_node_live` (Task 3.1.4) role-match check is a narrower identity check
    than wasm's `aria-ref=` locator (Task 4.2.1).** `verify_node_live` confirms the
    `BackendNodeId` still exists and its role is unchanged, but two structurally distinct
    elements could coincidentally share a role (e.g. two different buttons) — it is not a full
    identity guarantee, just a cheap, effective heuristic given CDP's `Accessibility` domain
    doesn't expose a persistent per-node identity token the way Playwright's internal
    `aria-ref=` engine does for wasm. This asymmetry between adapters is accepted as inherent to
    chromiumoxide's lower-level CDP surface (`research/pitfalls.md`'s native
    AX-tree-fidelity rabbit hole), not an oversight to fix in this pass.

11. **`click`/`type` timeout error wording has no pinned task/AC.** `design/ux.md` Error 4
    promises a specific string ("timeout after Ns waiting for click on ref ...") for a
    click/type that times out, but only Task 3.2.1 (`navigate`'s timeout) has an
    exact-string AC — Task 3.3.1/3.3.2 never construct or test this wording. An implementer
    could ship click/type timeouts with different phrasing than the design doc promises.
    Not a blocker (the underlying `tokio::time::timeout` wrapping already exists per Task
    3.3.1/3.3.2's "Wrap in timeout per the existing pattern" text) but should be tightened
    with an explicit AC before/during Story 3.3 implementation.

12. **wasm's error strings are not tested for byte-parity with native's canonical wording.**
    Task 4.3.1 maps JS-thrown errors to `PortError` variants by marker-word detection
    ("no session"/"blocked"/"crashed"), but nothing requires the JS glue to construct the
    *exact* `research/ux.md`-pinned strings (session-not-found, Error 5's two shapes) —
    only that the right `PortError` variant is chosen. Task 4.2.2 (this pass) now pins the
    Error-5 wording explicitly; session-not-found wording for wasm's `jsBrowserClick`/
    `jsBrowserType`/`jsBrowserSnapshot` should get the same treatment before Story 4.3/6.2 is
    considered done, so a caller sees identical error text regardless of which daemon
    (native or wasm) they're talking to.

13. **Opaque `ref` ids (`"e4"`, `"e9"`) carry no semantic information for a human reading a
    transcript after the fact.** `design/ux.md` explicitly cares about a secondary
    human-transcript-reader audience, but the plan's ref format doesn't help that reader
    tell which snapshot node a given `ref` pointed to without cross-referencing the
    snapshot's node list. Accepted as inherent to the ref-based locator design (matching
    `playwright-mcp`'s own opaque-ref convention, `requirements.md`'s "Locator format"
    resolution) — not a blocker, but a legibility cost worth naming rather than leaving
    implicit.

## Phase 1: Core Port & Schema Extensions

### Epic 1: Extend `BrowserDriver` and add shared types

#### Story 1.1: Add session/locator/snapshot types and extend `BrowserDriver`

- **Task 1.1.1** (`crates/core/src/ports.rs`): add `pub struct SessionId(pub String)`,
  `pub struct Locator(pub String)`, `pub struct AxNode { pub node_ref: String, pub role:
  String, pub name: String, pub value: Option<String>, pub children: Vec<AxNode> }`
  (`value` is `None` for non-form-control nodes such as buttons/generic containers, and
  `Some(current_text)` for textbox/combobox-like nodes — populated from the CDP AX node's
  own `value` property where present, per `research/ux.md`'s Surface 3 response contract,
  which requires the agent to be able to confirm typed text landed from the `type` call's
  own returned snapshot without a follow-up `snapshot` call), `pub struct AxSnapshot { pub
  root: AxNode, pub url: String, pub truncated: bool, pub navigated_from: Option<String> }`
  (`navigated_from` is `None` for every snapshot except one returned by `click`/`type_text`
  when that specific call's dispatch caused the page's URL to change — in which case it
  holds the pre-dispatch URL, giving the tool layer, Task 5.1.2, the one signal it needs to
  populate `BrowserActionOutput.note` without conflating "this action navigated" with the
  unrelated SSRF-`blocked` flag; see Task 3.1.5/3.3.1/3.3.2/4.2.1 for how each adapter

## Step 5 — ADR

No ADR is needed. Every technology choice here is either already-adopted
(`chromiumoxide`, `playwright-core`, no new Cargo/npm dependencies — confirmed in
`research/stack.md` and `research/build-vs-buy.md`) or a direct extension of an existing,
uncontested in-repo pattern (`Rc<RefCell<_>>` + `spawn_local`, the `SourceLocks`/RAII-guard
idiom, the `unknown_source_error` message shape, `Result<T, String>` at the tool layer).
The one genuinely new decision with a documented alternative-and-rejection — the
session-map/reaper concurrency design (Step 0.5) — is recorded in this plan's own
Pattern Decisions/Creative Pass section, which is sufficient; it does not rise to the level
of a standalone architecture decision record since it doesn't introduce a new dependency,
change a public interface contract outside this feature, or reverse a prior decision.
