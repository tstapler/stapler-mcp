## Additional plan defects noticed (not among the five)
- Story 1.1.4's acceptance criterion still specifies `[profile.release] strip = true` (workspace-wide), while the Phase 3 review resolution says to scope `strip` to `release-thin`. No task reconciles them, and the current `Cargo.toml` has the workspace-wide setting, which changes the daemon's release artifact (symbol-less crash backtraces) despite the "do not modify the daemon" non-goal. Decide one, update Story 1.1.4 and ADR-001, and make it a Task in Wave 1.
- Row 2's fix also resolves the plan's own rule "thin-client verification uses `-p stapler-mcp` alone", which currently depends on every human remembering it.
