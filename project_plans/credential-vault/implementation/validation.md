# Validation Plan: credential-vault

**Date**: 2026-09-08

## Happy Path Scenario
Given a daemon started with `OP_SERVICE_ACCOUNT_TOKEN` set and a live browser session on a page whose exact host matches a single 1Password Login item, when the calling LLM invokes `stapler_browser_type_secret` with a `CredentialRef{domain, field: CredentialField::Password}` and a `ref` from a prior snapshot, then `BrowserDriver::type_secret` resolves the credential internally, types it into the field, and returns an `AxSnapshot` whose acted-on node's value is `REDACTED_PLACEHOLDER` — the plaintext password never appears in the MCP request, the response, or any later `browser_snapshot`. *(One sentence — the anchor for all test design below.)*

## Test Stack
- **Unit**: Rust — `cargo test` with the crate's existing `#[cfg(test)] mod tests` convention (built-in `assert!`/`assert_eq!`, no external assertion library observed elsewhere in this codebase); fakes/stubs follow the existing `FakeBrowserDriver`/`StubBrowser` hand-rolled test-double pattern (no mocking framework in use). Wasm-side JS unit tests use this crate's existing Node `--test` harness convention in `crates/wasm/src/glue/*.test.js` (or inline, matching whatever convention Task 2.3.1c's investigation finds) with mock `page`/SDK-client objects, not a browser.
- **Integration**: Rust — `chromiumoxide`-driven tests in `crates/native/tests/` (real headless Chrome, shadow-DOM/autofill/TOTP fixtures) and `#[ignore]`d manual tests for the headless-vs-headed empirical check (Story 2.2.3); gated tests (Story 7.1.3) skip cleanly without `OP_SERVICE_ACCOUNT_TOKEN`. Wasm-side integration uses the same Node test harness driving real Playwright pages. Cross-adapter parity (Story 7.1.4) is a shared fixture table consumed independently by each language's own harness (no shared runtime).
- **E2E / UX**: N/A

## Coverage Targets and How to Measure

| Stack | Coverage command | Target |
|---|---|---|
| Rust (`crates/core`, `crates/native`, `crates/cli`) | `cargo tarpaulin --out Stdout` | ≥80% line |
| Wasm/JS glue (`crates/wasm/src/glue/*.js`) | Node's built-in `--experimental-test-coverage` (or this crate's existing coverage convention, if different — confirm before first run) | ≥80% line |

- All public service methods (`CredentialStore::resolve`, `BrowserDriver::type_secret`, `browser_type_secret`) — happy path + every named error path covered.
- All external integrations (`op` CLI via `spawn_and_capture`, `@1password/sdk` via `vault.js`) — unit mocked (fake `ProcessSpawner` / mocked SDK client) plus at least one real integration test per adapter (gated where a live vault is required).
- Both adapters (native/wasm) covered symmetrically for every cross-cutting guarantee (redaction key, domain check, dedup, dispatch-time refusal) — asymmetric coverage between adapters is itself a gap per `requirements.md`'s "identical wire protocol" success metric.
